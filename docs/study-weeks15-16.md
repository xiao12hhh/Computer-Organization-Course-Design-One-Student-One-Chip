# 第 15–16 周补学顺序

先用桌面入口看一次结果，再按下面顺序读代码。不要同时把 RTL、C++、AM、NES 全部打开。

## 1. 跟踪一次 addi 和一次 sw

读 npc/minirv/decode.sv、regfile.sv、top.sv。画出 PC → 取指 → 译码 → 寄存器读取 → 计算 → 写回的路径。说明哪些是组合逻辑，哪些在上升沿改变。观察为什么 x0 永远不变，以及为什么 sb 只改变一个字节。

## 2. 理解 DPI-C 与仿真时钟

找到 RTL 的 pmem_read/pmem_write/npc_trap 和 C++ 的对应函数。解释“C++ 驱动时钟”和“C++ 替 CPU 执行指令”的区别。组合逻辑会重复求值，为什么串口写入必须在提交边沿执行一次？为一个短程序加 --trace，用 GTKWave 看 PC、指令和寄存器。

## 3. 看懂 GOOD/BAD TRAP 和对照测试

运行 `python3 npc/minirv/test_core.py`，找到故意出错的用例。解释程序返回值、非法指令和超时分别代表什么。读 --diff 路径：为什么要比较 PC、所有寄存器和每一个写入字节，不能只看最后的 a0？

## 4. 理解只有八条指令为什么能跑游戏

比较 C 源码与 minirv 构建目录的汇编。编译工具把很多运算变成基本操作和查表，因此 CPU 本身无需直接实现乘除法。代价是动态指令数显著增加，这也是字符版运行慢的主要原因。不要把“38 个 RISC-V 测试通过转译”理解成 RTL 实现了所有原始指令。

## 5. 跟踪一次 printf 和一次时钟读取

从 printf 到 putch，再到对 0x10000000 的 sb，最后到宿主 putchar。时钟先读取高位触发快照，再读低位，解释为什么不能分别读取两个随时变化的半部。volatile 保证设备访问不会被编译器合并/省略，但它不等于多线程同步机制。

## 6. 分清两种马里奥运行路径

字符版：游戏 ROM → NES 模拟器 → minirv 机器码 → RTL NPC → 串口终端。图形版：游戏 ROM → NES 模拟器 → RV32IM 机器码 → NEMU → 显存/SDL 窗口。能说清每层正在模拟什么，就抓住了本阶段重点。

建议亲手做三件事：将一条 sb 的地址偏移从 0 改成 3 并解释字节变化；把 MMIO 测试的等待从 20 ms 改成 50 ms；改变字符渲染的采样步长并观察画面与输出量。修改后重跑相关测试，最后恢复基线。PA2 参考答案要结合这些实际操作，用自己的话重写。
