# 第 13–14 周补学清单

环境和代码已配好，可以先运行，再分五步读代码。以下是建议的学习顺序，不是已掌握记录。

## 1. 看懂一次监视点暂停

打开 Week13-Watchpoints，输入 `w $t0`、`c`、`info r`。说明为何 AUIPC 执行后 t0 变化、为何显示的 PC 已经指向下一条指令。再监视 `*0x80000010`，观察写内存后的变化。最后 `d 0` 并继续运行。

读 `pa1/nemu-watchpoint.c`：数组里的 32 个对象怎样通过指针形成两条链表？删除后为什么可以复用编号？为什么不能把 GOOD TRAP 的 END 改成 STOP？尝试添加 33 个常量监视点，解释最后一个为什么失败。

## 2. 从状态理解一条指令

状态是 PC、32 个通用寄存器和内存。每条指令都把旧状态变成新状态。读 `pa2/nemu-inst.c` 的取指和调用关系，再读 `pa2/rv32.c` 中 addi、lw、sw、beq、jalr 五种路径。

动手算一次 `addi x3,x1,-1`；写出指令字段和立即数补符号过程。解释为什么无符号加法的 32 位回绕是需要的，为什么 x0 不能被写入，为什么 JALR 的源与目的寄存器相同时必须先读取旧值。

## 3. 理解 M 扩展的边界

分别手算 `-7/3`、`-7%3`、除以零，以及 `0x80000000/-1`。再解释 MUL、MULH、MULHSU、MULHU 对操作数符号和结果高低半部的选择。运行 `python3 pa2/test_rv32.py`，对照测试里的 Python 大整数参考值。

## 4. 看懂 C 程序怎么成为机器码

阅读 `pa2/demo/main.c`，然后依次找到 AM 的 `start.S`、`_trm_init`、`main`、`halt`。理解编译、汇编、链接、ELF 转二进制、加载到 0x80000000、取指执行这条流程。打开 `pa2/demo/build/course-week14-riscv32-nemu.txt`，对照 C 源码看反汇编。

解释 AM 的作用：相同上层程序调用 `putch`、`halt` 等接口，具体平台提供底层实现。这里没有 Linux 进程和系统调用；AM 程序直接运行在模拟机器上。为什么 printf 最终变成一次对串口地址的写入？

## 5. 亲自改一次 klib 和程序

读 `pa2/klib/string.c` 中的 memmove，画出重叠范围并解释复制方向。读 `pa2/klib/format.c`，解释 snprintf 的返回值为什么可能大于缓冲区容量、为什么要保留结尾 NUL。

把示例的上限 100 改成 10，同时把断言 5050 改成 55，再编译运行；完成后恢复原测试。最后自己增加一个字符串边界测试，故意写错实现并确认测试会失败，再修回。

能独立说明这些问题并完成上述修改后，再继续第 15 周 RTL NPC。必答题参考不是个人报告；请用自己实际理解和操作的结果重写，学校题面补齐后再对齐提交要求。
